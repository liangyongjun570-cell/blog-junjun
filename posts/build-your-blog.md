> 这篇文章不是"理论教程"，而是我自己从零搭起这个网站的完整复盘。每一行配置、每一个坑，都是真实踩过再爬出来的。跟着做，一个晚上就能拥有和这个站同款的博客框架。

## 一、先搞清楚你在搭什么

很多人卡在建站第一步，是因为没搞明白一个博客背后到底有几个东西在跑。以我这个站为例，它其实是**三个服务**：

服务端口干什么的博客前端8500访客看到的网站本体（Next.js）控制台8400你自己的后台：写文章、传图、改相册（Next.js + 桌面壳）API 后端8300FastAPI，负责文件读写、同步、AI 接口代理

记住这张表，后面所有"为什么打不开"的问题，八成是其中一个服务没起来。

技术栈一句话概括：**Next.js 16 + React 19 + Tailwind CSS 4** 写前端，**FastAPI** 写后端，**Vercel** 免费托管，**GitHub** 存代码和评论数据。全程零服务器费用。

## 二、拿到源码并跑起来

我是从开源项目（heiehiehi 的模板，CC BY-NC 4.0，禁商用）克隆来的。你也可以 fork 或直接下载任何类似结构的模板。跑起来的关键三步：

```
# 1. 安装依赖（Node 建议 22+）
npm install

# 2. 把 dev 脚本写死端口，避免每次端口漂移
# package.json 里改成：
"dev": "next dev -p 8500"   # 博客端；控制台同理改成 -p 8400

# 3. 启动
npm run dev
```

> ⚠️ 坑 1：如果你的电脑用户名是中文（比如我），某些工具链会因非 ASCII 路径翻车。解决办法是把构建缓存重定向到纯英文路径，例如 `C:\Builds`。

打开 `http://localhost:8500` 看到页面，就算起飞成功。

## 三、把"别人的博客"变成"你的博客"

模板到手第一件事：**换血**。全站配置都集中在一个文件 `siteConfig.ts` 里，改它就够了：

```
export const siteConfig = {
  title: "你的站名",
  authorName: "你的昵称",
  bio: "一句话介绍自己",
  avatarUrl: "/avatar.jpg",        // 图片丢进 public/ 即可
  bgImages: ["/bg.jpg", "/bg2.jpg"], // 背景轮换图
  social: { github: "...", email: "...", qq: "...", wechat: "..." },
};
```

顺手做一次大扫除：原作者的统计脚本、友链、备案号、隐私信息，全部清掉。控制台如果也有独立的 `siteConfig.ts`，**记得两边同步改**——这是我后来发现控制台显示还是旧信息时踩的坑。

## 四、内容三件套：文章、碎碎念、相册

**文章**就是 Markdown 文件，扔进 `posts/` 目录自动成篇。frontmatter 长这样：

```
---
title: 我的第一篇
date: '2026-10-12 14:40:00'   # ← 必须带引号！
tags: [随笔]
cover: /images/xxx.jpg
description: 摘要
---
```

> ⚠️ 坑 2（血的教训）：`date` 不加引号，YAML 会把它解析成 Date 对象，页面直接 500。**日期必须用引号包起来**。

**碎碎念**（说说/短想法）放 `chatters/`，格式类似。**相册**在 `data/albums.ts` 里用数组维护，每张照片一个 `url` + 可选 `caption`。

如果模板带控制台，这三样都能在后台点点点搞定，不用手写文件——写完点「更新本地」同步到博客目录即可。

## 五、图片：图床与本地两条路

图片存储两条路：

1. **云图床**（兰空 Lsky Pro 等）：注册一个免费图床，拿到 API 地址和 Token，控制台里配好就能直传；
2. **本地图库**：图片直接存进 `public/images/`，路径写 `/images/xxx.jpg`。

> ⚠️ 坑 3：控制台（8400）和博客（8500）是两个服务，控制台预览本地图会裂。一劳永逸的解法是在控制台的 `next.config.ts` 里加一行代理：
>
> `ts async rewrites() { return [{ source: "/images/:path*", destination: "http://127.0.0.1:8500/images/:path*" }]; }`

上传建议做成批量——一次选一堆、拖拽一整沓，逐张显示进度，比一张一张传幸福一万倍。

## 六、音乐、天气这些"灵性"功能

**网易云歌单**：在 `siteConfig.ts` 填 `cloudMusicIds`（歌曲 ID 数组）。注意：**网易云返回的版权标记不可靠**，判断一首歌能不能播要实测——请求 `music.163.com/song/media/outer/url?id=xxx.mp3`，302 跳到 mp3 就是能播，跳到 404 就是锁了外链。我有一半候选歌是这样被筛掉的。

**真实天气**：注册和风天气开发者账号（免费），拿 Key 写进 `.env.local`：

```
QWEATHER_KEY=你的密钥
QWEATHER_HOST=你的专属请求主机
```

> ⚠️ 坑 4：改了环境变量必须**重启 dev 服务**才生效，热更新不会读 `.env.local`。

## 七、部署上线：Vercel + 域名 + 评论

本地玩爽了就该上线了，全程免费：

1. **推 GitHub**：注意国内网络先把 git 代理指向你的本地代理端口（如 `127.0.0.1:7897`）；
2. **Vercel 导入仓库**：环境变量（天气 Key、AI Key 等）在后台逐个添加；

   > ⚠️ 坑 5：环境变量加完**必须 Redeploy 一次**才生效，光保存没用。
3. **绑定域名**：买个喜欢的域名，DNS 按提示加 CNAME 指到 Vercel；
4. **Gitalk 评论**：去 GitHub 申请一个 OAuth App，clientID 填进配置，clientSecret **只放 Vercel 环境变量**，绝不能写进代码仓库。

   > ⚠️ 坑 6：评论框报 redirect\_uri 错误，多半是回调地址只登记了首页、实际页面在子路径。去 OAuth App 设置里勾选"允许通配符匹配"。

## 八、开始折腾：让它像"你的"

框架跑通只是起点，真正的乐趣在改造：

* 桌宠小猫解锁**全屏自由移动**，位置记进 localStorage，刷新也不跑丢；
* 音乐播放器改成**灵动岛**：Web Audio 分析器接真实频谱，鼓点一起全卡片跟着脉冲；
* 首页做成**杂志头版 + 横向时间轨道 + 电影胶片条 + 拍立得墙**，别人抄不走。

> ⚠️ 坑 7：想给 `<audio>` 接频谱分析器，音源必须允许跨域。网易云外链的 302 跳转不带 CORS 头，直接开会没声音——解法是后端先解析出最终 CDN 直链（带 `Access-Control-Allow-Origin: *`）再交给 audio。这类"跨域暗坑"遇到别慌，一层一层查响应头总能定位。

## 十、写在最后

建站最难的不是技术，是**开始**。这篇文章里的每一步，都可以只做一半就先用起来：先改个名字上线，文章慢慢写，样式慢慢调。我的小站也是从一个克隆的模板长成了现在的样子——有了会动的猫、会跳的频谱、会下雨的天气卡。
